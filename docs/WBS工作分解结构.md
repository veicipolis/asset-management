# 项目工作分解结构

版本：v0.1

本清单按交付成果分解工作。
WBS编号为稳定标识，不等于GitHub Issue编号。

实际执行负责人为本人。
后续在进度计划中另行分配模拟角色、工时、成本和依赖关系。
模拟完成状态与实际完成状态分别记录。

## M1 项目启动与计划

| WBS编号 | 工作项 | 交付物或验收条件 |
|---|---|---|
| 1.1 | 明确项目范围与核心业务验收标准 | 范围说明覆盖角色、流程、约束及验收条件 |
| 1.2 | 编制项目章程与模拟团队职责分工 | 明确目标、组织、模拟工期和预算依据 |
| 1.3 | 编制WBS并建立项目工作项清单 | 至少30个有意义工作项，关联阶段与Issue |
| 1.4 | 编制进度与资源计划 | Project中建立工期、依赖、资源及里程碑 |
| 1.5 | 编制成本计划与进度成本基准 | 工作项成本可汇总，保存初始基准 |
| 1.6 | 编制干系人与沟通管理计划 | 明确干系人、信息内容、频率及沟通渠道 |
| 1.7 | 建立风险登记册 | 至少记录Top5风险、应对措施及责任角色 |

## M2 需求与系统设计

| WBS编号 | 工作项 | 交付物或验收条件 |
|---|---|---|
| 2.1 | 细化用例与权限矩阵 | 明确角色、操作权限及越权处理 |
| 2.2 | 设计业务状态与转换规则 | 资产、领用和归还状态及非法转换明确 |
| 2.3 | 设计数据库与初始化脚本 | ER图、表结构、约束与脚本一致 |
| 2.4 | 设计系统架构与并发方案 | 明确分层职责、一万用户场景假设及扩展方式 |
| 2.5 | 设计核心类与业务接口 | 类图包含合理的抽象类、子类及接口 |
| 2.6 | 设计页面与请求接口 | 页面流程、请求参数、返回及错误处理明确 |

## M3 核心功能开发

| WBS编号 | 工作项 | 交付物或验收条件 |
|---|---|---|
| 3.1 | 初始化工程与首页 | Java21工程可启动，首页可访问，源码已托管 |
| 3.2 | 实现数据库结构与演示数据 | 脚本可在空数据库执行，不含真实隐私 |
| 3.3 | 实现用户登录与权限控制 | 登录有效，未登录及越权操作被拒绝 |
| 3.4 | 实现资产建档与信息维护 | 必填项、唯一编号和金额校验有效 |
| 3.5 | 实现资产条件查询 | 编号、名称、类别及状态筛选正确 |
| 3.6 | 实现领用申请 | 可提交申请，重复未结束申请被拒绝 |
| 3.7 | 实现领用审批 | 授权审批有效，禁止本人审批及重复审批 |
| 3.8 | 实现资产发放 | 原子更新状态与领用记录，防止重复发放 |
| 3.9 | 实现归还申请与接收 | 仅领用人可申请，接收后资产恢复闲置 |
| 3.10 | 实现关键操作日志 | 可追溯操作人、时间、对象及结果 |
| 3.11 | 完成分支与PR开发流程 | 同一开发任务至少3次有效提交，保留检查及合并记录 |

## M4 测试与项目监控

| WBS编号 | 工作项 | 交付物或验收条件 |
|---|---|---|
| 4.1 | 编写并执行业务与权限测试 | 覆盖核心流程、非法状态和越权请求 |
| 4.2 | 验证事务及竞争操作 | 竞争发放最多一次成功，失败操作不留部分更新 |
| 4.3 | 开展性能验证并分析差距 | 明确环境、负载、响应时间和错误率，不夸大结论 |
| 4.4 | 配置编码阶段监控视图 | 展示开发状态、模块进度、阻塞及工时偏差 |
| 4.5 | 编制中期跟踪报告 | 对比基准与模拟中期状态，区分实际进展 |
| 4.6 | 记录与评估项目变更 | 至少3份有具体原因、影响分析及处理决定的变更申请 |
| 4.7 | 修复缺陷并进行回归 | 保留复现、修复及验证结果，更新风险记录 |
| 4.8 | 开展每周进度检查与协调 | 保存7次模拟检查记录，包含偏差、阻塞及后续行动 |

## 范围说明

本清单共34个工作项。

维修、报废和统计属于已识别的扩展范围，
暂不纳入本轮核心开发工作包。
如决定实现，先记录变更，再新增WBS工作项并调整计划。

原有Issue复用，不为同一个工作项重复建单。
GitHub中的实际完成状态依据真实成果更新。

课程要求的模拟完成约20项，
在后续模拟状态字段和中期报告中单独体现，
不据此关闭尚未实际完成的Issue。
