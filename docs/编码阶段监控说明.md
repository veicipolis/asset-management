# 编码阶段监控说明

关联工作项：[4.4]。

## 1. 监控方式

使用 GitHub Project 的“编码阶段监控”表格视图，
筛选核心开发工作项，并按模块分组。

该视图与原看板共享任务，状态同步更新。

## 2. 字段与用途

| 字段 | 用途 |
|---|---|
| Status | 跟踪真实开发状态 |
| Assignees | 标明实际负责人 |
| 模块 | 按功能查看开发进展 |
| 优先级 | 安排处理顺序 |
| 计划工时(h) | 引用Project中的模拟团队计划工时 |
| 实际工时(h) | 仅记录有依据的真实投入 |
| 阻塞原因 | 说明当前真实阻塞 |

已为[3.4]、[3.6]、[3.7]、[3.8]、[3.9]、[3.10]
填写模块、优先级及计划工时。

## 3. 更新规则

- 开始实际开发时设置为In Progress。
- 完成实现、验证和提交后，按验收条件设置为Done。
- 出现阻塞时填写原因，解除后清理并在Issue中保留处理记录。
- 未记录实际工时的任务留空，不以0代替未知。

## 4. 数据口径与限制

GitHub状态反映实际开发情况，
不与Project的课程模拟完成百分比混用。

计划工时为模拟团队投入，实际工时为个人真实投入，
两者当前不可直接比较，不计算工时偏差。

当前视图已支持开发状态、模块和阻塞监控；
WBS要求的工时偏差展示尚未完成，需要另行建立同口径的数据。
