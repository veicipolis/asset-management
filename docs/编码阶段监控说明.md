# 编码阶段监控说明

关联工作项：[4.4]。

## 1. 监控方式

使用 GitHub Project 的“编码阶段监控”表格视图，
筛选核心开发工作项，并按模块分组。

该视图与原看板共享任务，状态同步更新。

## 2. 字段与用途

| 字段 | 用途 |
|---|---|
| Status | 跟踪真实开发状态 |
| Assignees | 标明实际负责人 |
| 模块 | 按功能查看开发进展 |
| 优先级 | 安排处理顺序 |
| 计划工时(h) | 引用Project中的模拟团队计划工时 |
| 实际工时(h) | 仅记录有依据的真实投入 |
| 阻塞原因 | 说明当前真实阻塞 |

已为[3.4]、[3.6]、[3.7]、[3.8]、[3.9]、[3.10]
填写模块、优先级及计划工时。

## 3. 更新规则

- 开始实际开发时设置为In Progress。
- 完成实现、验证和提交后，按验收条件设置为Done。
- 出现阻塞时填写原因，解除后清理并在Issue中保留处理记录。
- 未记录实际工时的任务留空，不以0代替未知。

## 4. 数据口径与限制

GitHub状态反映实际开发情况，
不与Project的课程模拟完成百分比混用。

计划工时为模拟团队投入，实际工时为个人真实投入，
两者当前不可直接比较，不计算工时偏差。

当前视图已支持开发状态、模块和阻塞监控；
同口径的模拟偏差分析见第五节

## 5. 编码阶段工时偏差模拟

以下为课程模拟案例，不是本人实际工时记录，
也不回写现有Project中期跟踪文件。

比较时采用相同任务范围、相同模拟团队口径，
假设下列任务均已完成，再比较计划工时与模拟实际工时。
计划值引用当前估算，不称为已保存的基准。

工时偏差 = 模拟实际工时 - 计划工时。
正值表示超出计划，负值表示节省。

| 工作项 | 计划工时(h) | 模拟实际工时(h) | 偏差(h) | 模拟原因与措施 |
|---|---:|---:|---:|---|
| [3.4] 资产建档与信息维护 | 36 | 40 | +4 | 版本冲突提示联调增加投入，补充统一提示规则 |
| [3.6] 领用申请 | 24 | 26 | +2 | 补充重复申请边界检查，复用校验逻辑 |
| [3.7] 领用审批 | 24 | 24 | 0 | 按计划完成 |
| [3.8] 资产发放 | 30 | 34 | +4 | 事务与并发场景联调增加投入，集中检查锁顺序 |
| [3.9] 归还申请与接收 | 36 | 34 | -2 | 复用状态校验和日志机制 |
| [3.10] 关键操作日志 | 16 | 16 | 0 | 按计划完成 |
| 合计 | 166 | 174 | +8 | 模拟投入比计划增加约4.82% |

本表是独立的任务完成后偏差演练，
不是2026年11月20日中期状态的工时汇总。

GitHub中的真实任务状态保持按实际开发结果维护；
未知的个人真实工时继续留空。
模拟数据使用明确标注的独立字段或视图展示。

偏差处理：
1. 优先复用状态校验、异常提示和日志组件。
2. 提前核对并发与事务边界，减少联调返工。
3. 超出计划的工作记录原因，不通过修改原计划消除偏差。
