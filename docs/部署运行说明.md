# 部署运行说明

## 1. 环境与访问方式

- 本地开发：Java 21、IDEA、Maven Wrapper。
- 云端：Debian 12、Docker 26.1.3、Docker Compose 2.27.1。
- 云端数据库：MySQL 8.4。
- 应用镜像：asset-management:0.1.0。
- 部署目录：/opt/asset-management。

应用仅绑定服务器 127.0.0.1:8080，通过 SSH 隧道访问。
MySQL 不映射宿主机端口。

当前未配置公网 HTTPS，SSH 隧道仅用于受控访问及演示。

## 2. 本地打包

在项目根目录运行：

```powershell
.\mvnw.cmd clean package "-DskipTests"
```

生成：

```text
target/asset-management-0.0.1-SNAPSHOT.jar
```

该命令跳过测试执行。发布前应另行运行测试并核对结果。

## 3. 上传部署文件

服务器目录结构：

```text
/opt/asset-management/
├── Dockerfile
├── .dockerignore
├── compose.yaml
├── .env
├── target/
│   └── asset-management-0.0.1-SNAPSHOT.jar
├── db-init/
│   ├── 01_schema.sql
│   ├── 02_asset_and_application.sql
│   ├── 03_loan_return_log.sql
│   └── 04_seed_basic.sql
├── 05_seed_users.sql
└── backups/
```

本地 schema.sql 上传时命名为 01_schema.sql，保证执行顺序。
SQL 文件使用 UTF-8，并在开头设置：

```sql
SET NAMES utf8mb4;
```

05_seed_users.sql 不放入自动初始化目录。

## 4. 配置数据库密码

仅在服务器创建 .env：

```text
MYSQL_ROOT_PASSWORD=独立的数据库管理员密码
ASSET_DB_PASSWORD=独立的应用数据库密码
```

使用随机强密码，并设置：

```bash
chmod 600 /opt/asset-management/.env
```

.env 不提交 Git，不将其内容写入报告或日志。
数据库密码与网页登录密码分别管理。

## 5. 构建和启动

```bash
cd /opt/asset-management
docker build -t asset-management:0.1 .
docker compose config --quiet
docker compose up -d db
docker compose ps
```

待数据库为 healthy 后：

```bash
docker compose up -d app
docker compose logs --tail=80 app
curl -s -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8080/login
```

预期应用启动成功，登录页返回 HTTP 200。

MySQL 初始化脚本仅在数据目录为空时自动执行。
已有数据库不会因修改初始化脚本而自动更新。

## 6. 首次初始化演示账号

在本地运行 PasswordHashTool，通过运行配置中的 DEMO_PASSWORD
提供云端演示密码，取得 BCrypt 哈希。

服务器执行：

```bash
cd /opt/asset-management
docker compose cp ./05_seed_users.sql db:/tmp/05_seed_users.sql
docker compose exec -e MYSQL_HISTFILE=/dev/null db sh -c \
  'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql --default-character-set=utf8mb4 -u "$MYSQL_USER" asset_management'
```

确认 app_user 为空后，在同一个 MySQL 会话中执行：

```sql
SET @demo_password_hash = '完整的BCrypt哈希';
SOURCE /tmp/05_seed_users.sql;
```

确认没有 SQL 错误且账号、角色正确后：

```sql
COMMIT;
```

发生错误则执行 ROLLBACK，排查后再初始化。
退出并重新连接，确认账号确实已保存。

演示账号：

| 账号 | 角色 |
|---|---|
| employee | 普通员工 |
| employee2 | 普通员工 |
| approver | 普通员工、部门审批人 |
| assetadmin | 资产管理员 |
| sysadmin | 系统管理员 |

上述账号在当前受控演示环境中共用初始化时指定的演示密码。
公网开放前应调整账号与密码管理方案。

## 7. 通过 SSH 隧道访问

本机 PowerShell 执行，将 SERVER_IP 替换为服务器 IPv4：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18080:127.0.0.1:8080 root@SERVER_IP
```

保持窗口运行，浏览器访问：

```text
http://127.0.0.1:18080/login
```

若服务器登录页返回 200，但本机连接被拒绝，检查隧道是否断开、
本地端口是否被占用，以及是否使用正确的 18080 端口。

## 8. 日常检查与重启

```bash
docker compose ps
docker compose logs --tail=80 app
docker compose logs --tail=80 db
```

重启数据库后，等待其 healthy，再重启应用：

```bash
docker compose restart db
docker compose ps
docker compose restart app
```

应用重启后重新登录，检查历史领用和日志仍存在。

不要执行 docker compose down -v：
该选项会删除 Compose 管理的数据卷。

## 9. 数据库备份

在服务器部署目录执行：

```bash
mkdir -p backups
chmod 700 backups
umask 077

backup_file="backups/asset_management_$(date +%Y%m%d_%H%M%S).sql"

if docker compose exec -T db sh -c \
  'MYSQL_PWD="$MYSQL_PASSWORD" exec mysqldump \
  --default-character-set=utf8mb4 \
  --single-transaction \
  --no-tablespaces \
  --set-gtid-purged=OFF \
  -u "$MYSQL_USER" asset_management' > "${backup_file}.partial"
then
  mv -- "${backup_file}.partial" "$backup_file"
  ls -lh "$backup_file"
else
  echo "备份失败，.partial 文件不作为有效备份"
fi
```

备份包含账号密码哈希与业务数据，不提交 Git。
当前备份保存在同一服务器，尚未实现异机备份。

## 10. 恢复验证原则

- 先检查备份是否含 USE、CREATE DATABASE、DROP DATABASE 等数据库定向语句。
- 恢复到新建的独立验证库，不覆盖运行库。
- 已使用 asset_management_restore_check 完成一次导入验证。
- 已核对六张关键表的记录数及演示资产名称的 UTF-8 字节。
- 该验证不等于全库逐字段校验，也不等于应用切换后的业务验收。

具体实测结果见《云端部署验证记录.md》。

## 11. 已知限制

- 当前通过 SSH 隧道访问，尚未提供公网 HTTPS 入口。
- 镜像标签尚未固定到 digest，后续重新拉取可能获得不同补丁版本。
- 本地 Repository 性能测试不代表云端 HTTP 性能或并发承载能力。
- 未进行服务器故障、数据卷丢失及异机灾难恢复演练。
