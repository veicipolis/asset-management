# 企业固定资产全生命周期管理系统项目范围说明书

版本：v0.1
状态：初始范围基准
关联任务：明确项目范围与核心业务验收标准

## 1. 项目目标

为企业固定资产建立统一档案，记录资产从建档、领用、
归还到维修和报废的业务过程，提高资产状态与责任人的可追溯性。

本项目用于软件项目管理综合实验。实际由本人独立完成，
本人担任项目经理；多人团队、工期和成本按课程要求进行模拟。
模拟管理记录与实际开发、测试结果分别标注。

## 2. 用户角色与权限

| 角色 | 权限 |
|---|---|
| 普通员工 | 查询可领用资产，提交领用及归还申请，查看本人申请与领用记录 |
| 部门审批人 | 查看并审批本部门员工的领用申请，不得审批本人申请 |
| 资产管理员 | 维护资产档案，确认资产发放与归还，管理维修和报废记录 |
| 系统管理员 | 管理用户、部门、角色及权限 |

用户仅能访问权限范围内的数据，权限限制在服务端执行。

## 3. 开发范围

### 3.1 本次优先实现

1. 用户登录及角色权限控制。
2. 资产建档，记录资产编号、名称、类别、购置日期、
   原值、存放位置和状态。
3. 按编号、名称、类别和状态查询资产。
4. 员工提交领用申请，部门审批人批准或驳回申请。
5. 资产管理员确认发放，系统更新资产状态和领用人。
6. 员工提交归还申请，资产管理员确认接收。
7. 保存审批、发放、归还和关键档案变更的操作记录。
8. 系统管理员在线维护用户、部门和资产类别，
   分配已有角色；支持用户启用停用及管理操作审计。
   具体边界见《用例与权限矩阵》第六节。

### 3.2 扩展范围

1. 维修登记、维修完成及维修费用记录。
2. 报废申请、审批及报废确认。
3. 按类别、部门和状态进行资产数量统计。

扩展功能在核心流程完成后按剩余时间实施。
未实现的功能在交付说明中明确列出。

### 3.3 本次不实现

1. 复杂折旧、税务和财务核算。
2. 与真实采购、财务或人力资源系统对接。
3. 真实支付、短信和硬件扫码设备接入。
4. 多企业租户管理及移动端应用。

## 4. 核心业务流程

### 4.1 资产建档

资产管理员录入资产信息，系统校验资产编号唯一性和必填项。
建档成功后，资产初始状态为“闲置”。

### 4.2 资产领用

员工选择闲置资产并提交申请。
提交申请不占用资产。
审批人批准或驳回申请，驳回时填写原因。
批准后，资产管理员确认发放。
发放成功后，资产状态变为“在用”，记录领用人和发放时间。

### 4.3 资产归还

员工对本人正在领用的资产提交归还申请。
管理员确认实物接收后，结束领用记录，资产状态恢复为“闲置”。
待确认期间，资产仍为“在用”。

## 5. 状态与业务约束

### 5.1 状态定义

- 资产状态：闲置、在用、维修中、已报废。
- 领用申请状态：待审批、已驳回、待发放、已发放、已取消。
- 归还申请状态：待确认、已完成、已取消。

### 5.2 业务约束

1. 资产编号唯一，购置原值不得为负数。
2. 同一资产同一时间最多存在一条有效领用记录。
3. 申请获批不代表资产已发放。
4. 发放时必须重新检查资产为闲置，避免重复分配。
5. 同一员工不能对同一资产重复提交未结束的领用申请。
6. 普通员工不能审批申请或修改资产状态。
7. 仅当前领用人能够提交该资产的归还申请。
8. 同一领用记录最多存在一条待确认的归还申请。
9. 维修中、已报废资产不能发放。
10. 已报废资产不能恢复使用。
11. 已产生业务记录的资产不直接物理删除，历史记录保留。
12. 重复审批、发放或归还操作不得产生重复业务记录。
13. 发放和归还涉及的状态更新、业务记录及操作日志
    应在同一数据库事务中完成。

## 6. 核心验收标准

| 编号 | 验收内容 | 通过条件 |
|---|---|---|
| AC01 | 资产建档 | 合法信息可保存，重复编号和非法金额被拒绝 |
| AC02 | 资产查询 | 可按条件查询并显示正确状态 |
| AC03 | 领用申请 | 员工可提交申请，重复的未结束申请被拒绝 |
| AC04 | 领用审批 | 有权限者可审批，无权限者及本人审批被拒绝 |
| AC05 | 资产发放 | 成功后资产在用且存在有效领用记录 |
| AC06 | 重复发放 | 两次竞争发放最多一次成功，不产生重复领用 |
| AC07 | 资产归还 | 接收后资产闲置，原领用记录结束 |
| AC08 | 权限控制 | 未登录或越权请求不能完成受保护操作 |
| AC09 | 操作追踪 | 可追溯关键操作的人员、时间、对象和结果 |
| AC10 | 构建运行 | 按运行说明可构建并启动项目，核心流程可演示 |

## 7. 并发与质量目标

按课程要求，在架构设计中考虑一万用户同时使用的场景，
分析查询、写入比例、数据库索引、连接池及部署扩展方式。

“一万用户同时使用”不直接等于每秒一万次请求。
性能验证时明确用户行为、请求频率、数据量、测试环境、
响应时间和错误率。

本地功能演示不能证明系统已达到一万用户并发目标。
报告分别记录设计目标、实际测试规模和测得结果。
