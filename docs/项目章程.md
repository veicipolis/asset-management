# 企业固定资产全生命周期管理系统项目章程

版本：v0.1
状态：初稿

## 1. 项目背景

企业固定资产在建档、领用、归还、维修和报废过程中，
需要维护准确的资产状态、使用责任人和历史记录。

本项目建设固定资产管理系统，并按照软件项目管理综合实验要求，
开展项目启动、计划、执行、监控和收尾管理。

## 2. 项目目标

1. 建立统一的资产档案，支持资产信息维护和查询。
2. 实现领用申请、审批、发放与归还的核心业务闭环。
3. 实现角色权限控制及关键操作记录。
4. 完成系统架构、数据库设计和核心代码。
5. 建立可追踪的任务、版本、缺陷和变更记录。
6. 形成项目管理材料、可运行程序及实验报告。

## 3. 项目实施方式

本项目实际由本人独立完成，本人担任项目经理，
承担实际的需求分析、设计、开发、测试及文档工作。

按课程要求设置模拟团队、工期、工作量和成本。
模拟数据与实际开发、提交和测试记录分别标注，
不将模拟成员职责描述为真实参与成果。

## 4. 团队组织与职责

下表为模拟团队安排。
同学A至同学E为临时占位代号，后续对应同班同学。

| 成员 | 模拟角色 | 模拟职责 |
|---|---|---|
| 本人 | 项目经理 | 制定计划、协调任务、监控进度与组织验收 |
| 同学A | 需求分析人员 | 分析需求、整理业务流程和验收标准 |
| 同学B | 系统设计人员 | 设计架构、数据库和接口 |

涉及范围、工期或成本的变更须记录影响及处理决定。

## 5. 项目范围

核心范围包括：
- 用户登录与角色权限。
- 资产建档和查询。
- 领用申请、审批与发放。
- 资产归还。
- 关键操作记录。

维修、报废及统计作为扩展功能，按剩余时间实施。
详细业务约束和验收标准见《项目范围说明书》。

## 8. 技术与管理工具

- 开发环境：IntelliJ IDEA、Java 21、Maven。
- 应用框架：Spring Boot、Thymeleaf、Spring Data JPA。
- 数据库：MySQL。
- 代码版本管理：Git。
- 代码托管与任务管理：GitHub。
- 任务跟踪：GitHub Issues与Projects。
- 代码变更流程：分支、Pull Request、检查与合并。
- 进度计划：Microsoft Project。

数据库密码通过环境变量配置，不提交至代码仓库。

## 9. 项目监控方向

学号后两位为23，除以3余2。
按课程要求，仪表盘面向代码编写阶段配置。

重点跟踪：
1. 开发任务状态及完成数量。
2. 各模块的开发进度。
3. 阻塞任务及原因。
4. 预计工时与实际工时偏差。
5. 代码提交、Pull Request及构建结果。

各项信息通过Projects字段、视图、统计图表，
以及关联的Pull Request和Actions记录展示。

## 10. 主要风险与应对

| 风险 | 应对措施 |
|---|---|
| 功能范围持续增加 | 优先完成核心流程，新增功能走变更记录 |
| 单人开发时间不足 | 按优先级推进，扩展功能允许延期 |
| 数据状态不一致 | 使用事务、状态校验及针对性测试 |
| 开发环境出现问题 | 保留运行说明，及时提交可运行版本 |
| 管理材料与开发脱节 | 完成任务时同步更新Issue、文档和测试记录 |

## 11. 并发设计目标

按课程要求考虑一万用户同时使用的场景。
设计时分析用户行为、请求频率、数据库访问和扩展方式。

设计目标与实际测试结果分别记录，
未经测试不宣称已达到一万用户并发。

## 12. 主要交付成果

1. 项目源码及可构建版本。
2. 数据库结构脚本与演示数据。
3. 需求、架构及核心类设计文档。
4. 测试用例、缺陷及验证结果。
5. GitHub任务、提交和Pull Request记录。
6. WBS、进度、资源与成本计划。
7. 风险、沟通、变更和中期跟踪材料。
8. 运行说明、验收记录及课程实验报告。

## 13. 项目完成标准

1. 核心业务符合范围说明中的验收条件。
2. 严重影响核心流程的缺陷已修复。
3. 源码能够按运行说明构建并启动。
4. 管理记录可追踪，模拟与实际数据区分清楚。
5. 交付文件齐全，未完成事项与限制已明确说明。
