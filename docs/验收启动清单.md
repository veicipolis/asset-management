# 重启后验收启动清单

## 一、本地验收

### 1. 启动MySQL

以管理员身份打开PowerShell：

```powershell
Start-Service -Name mysql95
Get-Service -Name mysql95
```

预期状态为Running。

管理员权限用于启动Windows服务。
后续运行IDEA、网页登录及普通数据库连接不需要管理员权限。

### 2. 启动应用

打开IDEA中的 D:\workshop\asset-management 项目。

选择 AssetManagementApplication 运行配置，
确认使用Java 21，环境变量中保留：

- ASSET_DB_PASSWORD：本地应用数据库账号的密码。
- ASSET_DB_USERNAME：如已配置，使用之前验证成功的账号。
- ASSET_DB_URL：如已配置，使用本地 asset_management 数据库地址。

未覆盖用户名时，默认数据库账号为asset_app。
数据库密码不是网页登录密码。

运行应用，等待出现应用启动成功信息。
正常验收无需重新执行测试或初始化SQL。

浏览器访问：

http://127.0.0.1:8080/login

### 3. 可选：连接数据库检查

普通PowerShell执行：

```powershell
mysql --default-character-set=utf8mb4 -h 127.0.0.1 -P 3306 -u asset_app -p asset_management
```

按提示输入本地应用数据库密码，输入时不显示字符。

若提示找不到mysql命令，使用此前安装目录中mysql.exe的完整路径，
或使用IDEA已配置的数据库连接。

退出数据库：

```sql
exit;
```

## 二、云端验收

本地电脑重启通常不会停止云端服务器，
但会断开原来的SSH连接与隧道。

云端验收不需要启动本地MySQL或本地Java应用。

### 1. 登录服务器

在本机普通PowerShell中执行，
将SERVER_IP替换为服务器IPv4地址：

```powershell
ssh root@SERVER_IP
```

输入服务器登录密码，或使用已配置的SSH密钥。
服务器登录密码与数据库、网页密码分别管理。

### 2. 检查容器

登录后执行：

```bash
cd /opt/asset-management
docker compose ps
```

预期：
- db为Up且healthy。
- app为Up。
- app端口为127.0.0.1:8080->8080/tcp。

如果Docker服务没有运行：

```bash
systemctl start docker
```

如果容器未启动：

```bash
cd /opt/asset-management
docker compose up -d
docker compose ps
```

等待数据库healthy和应用完成启动后检查：

```bash
curl -s -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8080/login
```

预期HTTP 200。
应用刚启动时可以稍等再检查。

正常验收不需要重新build、导入SQL或初始化账号。
不要执行docker compose down -v，以免删除数据库数据卷。

### 3. 建立SSH隧道

在本机另开一个普通PowerShell窗口：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18080:127.0.0.1:8080 root@SERVER_IP
```

替换SERVER_IP后执行，保持该窗口打开。
连接成功后没有输出、一直停留在窗口中属于正常情况。

本机浏览器访问：

http://127.0.0.1:18080/login

不要直接用服务器公网IP访问8080：
当前应用只监听服务器回环地址，通过SSH隧道访问。

## 三、演示账号

| 账号 | 用途 |
|---|---|
| employee | 员工申请与归还 |
| employee2 | 第二部门员工及权限边界演示 |
| approver | 部门审批 |
| assetadmin | 资产维护、发放及归还接收 |
| sysadmin | 用户、角色及基础数据管理 |

使用各环境已经验证成功的网页登录密码。
本地和云端密码可能不同，不在Git文档中保存明文密码。

验收前确认员工与审批人的部门匹配。
不同角色使用不同浏览器配置文件或独立浏览器登录；
同一浏览器的普通标签页通常共享登录会话。

## 四、建议验收顺序

1. 登录并查看角色对应首页入口。
2. 查询资产，检查中文、分类和存放位置正常。
3. 使用闲置资产提交领用申请。
4. 同部门审批人批准申请。
5. 资产管理员发放，检查资产变为使用中。
6. 员工申请归还，资产管理员接收。
7. 检查资产恢复闲置，领用记录已结束。
8. 检查相关成功日志。
9. 查看系统管理页面及已准备的测试、部署记录。

复用演示数据前检查资产当前状态，
不要假设之前使用过的资产仍然闲置。

本地与云端数据库互相独立，
一个环境的操作不会自动同步到另一个环境。

## 五、常见问题

| 现象 | 优先检查 |
|---|---|
| 本地页面连接被拒绝 | IDEA应用是否运行、是否访问8080 |
| 本地数据库连接失败 | mysql95是否Running，应用运行配置中的数据库密码是否保留 |
| 应用提示8080被占用 | 是否已运行另一个应用实例，优先在IDEA停止旧实例 |
| 云端返回200，但本机网页打不开 | SSH隧道是否仍在运行，浏览器是否访问18080 |
| 隧道提示端口占用 | 是否已有隧道窗口，先确认旧隧道是否可用 |
| 网页账号无法登录 | 是否混用了本地与云端密码，账号是否启用 |
| 审批人看不到申请 | 申请是否待审批、申请部门是否与审批人匹配 |
| 云端应用异常 | 查看app及db容器日志 |

云端日志检查：

```bash
cd /opt/asset-management
docker compose logs --tail=80 app
docker compose logs --tail=80 db
```

## 六、验收结束

- 本地：在IDEA停止应用，保存文件后退出。
- 隧道：在隧道PowerShell窗口按Ctrl+C。
- SSH终端：输入exit退出。
- 云端容器可继续运行；关闭本机窗口不会停止云端容器。
- Project文件保存后正常关闭，避免Git操作时被占用。
