# 干系人与沟通管理计划

版本：v0.1

## 1. 实施说明

项目实际由本人独立完成。
指导教师的反馈按真实情况记录；
虚拟团队和业务用户的沟通按课程模拟场景记录，
不将计划中的会议写成已经发生的会议。

## 2. 干系人登记表

| 干系人 | 主要关注点 | 需要的信息 |
|---|---|---|
| 指导教师 | 课程指标、管理过程、报告与验收质量 | 阶段成果、待确认问题、验收材料 |
| 本人（项目经理） | 范围、进度、成本、风险和交付 | 任务状态、阻塞、偏差及处理结果 |
| 模拟需求分析人员 | 需求完整性和业务规则 | 范围说明、用例、需求变更 |
| 模拟系统设计人员 | 架构及数据一致性 | 业务约束、设计评审意见、接口约定 |
| 模拟前后端开发人员 | 开发任务及接口衔接 | 设计文档、验收条件、缺陷与优先级 |
| 模拟测试人员 | 可测试性和质量 | 测试环境、版本、测试用例、修复记录 |
| 模拟业务用户 | 流程易用性、权限及数据准确性 | 页面原型、操作说明、验收结果 |

## 3. 沟通安排

| 场景 | 内容 | 频率或触发条件 | 渠道与记录 | 责任角色 |
|---|---|---|---|---|
| 课程要求确认 | 日期口径、工具及成果要求 | 出现影响方案的疑问时 | 课程指定渠道，反馈摘要存入docs | 项目经理 |
| 需求与设计评审 | 范围、业务规则、架构和接口 | 设计成果形成或发生重要变更时 | Issue讨论与设计文档 | 需求分析、系统设计 |
| 周期性进度检查 | 进度偏差、阻塞、风险和后续行动 | 按[4.8]的7次计划执行 | Projects及检查记录 | 项目经理 |
| 开发衔接 | 接口、数据格式、页面与后端联调 | 开始联调或接口变化时 | Issue、PR及接口文档 | 开发人员 |
| 缺陷处理 | 复现步骤、影响、修复和验证结果 | 发现缺陷及状态变化时 | 缺陷Issue与关联提交 | 开发、测试 |
| 变更评估 | 原因、范围及进度成本影响 | 收到变更申请时 | docs/changes及关联Issue | 项目经理 |
| 验收与交付 | 验收结果、遗留问题、运行方法 | 发布前及项目收尾时 | 验收记录、Release及运行说明 | 项目经理、测试 |

## 4. 记录规则

每次沟通记录至少包含：
- 真实记录日期或明确标注的模拟状态日期。
- 讨论事项及关联Issue。
- 结论、待解决问题和后续行动。
- 实际责任人或模拟责任角色。
- 计划完成时间及跟踪结果。

重要决定同步更新相关文档，不只保存在聊天记录中。
敏感信息、密码和私人联系方式不写入公开仓库。

## 5. 问题升级与跟踪

一般问题在对应Issue中记录和处理。
影响核心流程、阶段交付或预算的问题，
由项目经理记录影响并决定是否提出变更。

涉及课程要求解释的问题向指导教师确认，
收到反馈前标为待确认，不虚构批准结果。

## 6. 工时统计边界

本计划定义沟通规则，本身不额外增加会议工时。
周期检查工时已计入[4.8]。
设计评审、联调及缺陷沟通须在对应任务估算中说明，
不与其他工作项重复计算。
